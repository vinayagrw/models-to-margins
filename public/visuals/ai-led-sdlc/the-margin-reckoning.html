05 — The translation storywatch the margin leak, then hold

AI translated 12,000 lines in an afternoon. The margin lived in the one line it dropped.

Volume is the easy part — the model converts a legacy tax engine in minutes and every test goes green. The value hides in a rule that lived only in tribal knowledge. Step through the three moments where the output looks finished and the margin quietly leaks past the gate.

LEGACY // tax-engine.cob → .ts

The model converts the whole module in one pass.

COBOL in, TypeScript out. The diff is clean, the unit tests it generated all pass, and the velocity dashboard lights up. Every signal an output metric can see says done.

function calculateTax(amt, region) { const rate = 0.05; if (region === 'X8') { return amt * (rate + 0.005); // local surcharge } return amt * rate; } // ✓ 41/41 generated tests pass · merged on green

One rule never made the crossing — and no test knew to miss it.

A 1999 exemption lived in a single COBOL paragraph that no requirement, ticket, or test ever described. The model couldn't translate context it was never given. The code runs, the tests pass, and 47 accounts are silently overcharged — value leaking exactly where no output metric is looking.

* COBOL (legacy): IF SPECIAL-CODE = 'Y2' MOVE 0 TO TAX. ↑ dropped in translation — lived in no test, no ticket, no spec const rate = 0.05; return amt * rate; // Y2-exempt accounts now taxed at full rate } // ✓ tests still green — the gap is invisible to the dashboard

A human who remembers 1999 restores the line.

The gate isn't ceremony — it's the one place the why behind a legacy line still exists. A senior engineer reads the output against intent, recognizes the missing exemption, and injects the context the model never had. This is the work that converts volume into margin — and the reason the governed line is the 5% path.

function calculateTax(amt, region, code) { // Human override: restored the 1999 Y2 exemption if (code === 'Y2') return 0; const rate = 0.05; if (region === 'X8') { return amt * (rate + 0.005); } return amt * rate; } // ✓ verified against intent, not just against tests
★
AI is a Copilot, not an Autopilot for legacy work. The model multiplies output; it cannot supply the context it was never told. That context — the reason a line exists — is the margin, and it's exactly the work the human gate exists to protect.

How to collect — eight steps
  1. Freeze a baseline of at least one pre-AI quarter per phase. No before, no attribution.
  2. Tag authorship at source — commit trailer or PR label — so every downstream metric slices by cohort.
  3. Auto-pipe the four DORA keys from CI/CD and the incident tool. No manual, gameable spreadsheet.
  4. Add the counter-metric for every lead you switch on. Never ship a speed number alone.
  5. Run a controlled comparison — staggered-adoption or diff-in-diff, never naive before/after.
  6. Layer experience and cost — a quarterly DXI/SPACE survey, plus token, run and review spend.
  7. Report distributions, refresh weekly, re-baseline quarterly. Magnitudes perish, methods endure.
  8. Wire a governance feed — identity, provenance and audit of agent output. A measurement input now, a legal one soon.

11 — Pilot to scalewhy 95 of 100 stall

Five questions before you scale an agent pilot.

A pilot proves the tool works. These prove the organisation can absorb it safely and profitably — the filter into the lit 5% that reach the margin.

1

Integrated, or a standalone demo?

Winners wire the agent into the real SDLC — issue → branch → CI → PR → deploy — carrying org context and replacing a step.

Good looks like: in the workflow, not beside it.
2

ROI proven — and cost modelled at 1,000 users?

Agentic load is per-run and unbounded; per-seat budgeting breaks. Model token + orchestration + review cost before you sign.

Good looks like: P&L-grade ROI + budget guardrails up front.
3

Safe across hundreds — identity, provenance, audit?

Most agents are over-permissioned with no machine-identity strategy. Frameworks now ship their own CVEs, and EU AI Act high-risk duties are landing.

Good looks like: governed non-human identities, least privilege, full audit trail.

Genuinely used and trusted — junior rung safe?

Adoption ≠ value — trust fell 40% → 29% as usage rose.4 Measure active use, not seats, and guard the entry path.

Good looks like: daily-use + trust metrics, champions, a junior plan.

Platform & review capacity to absorb the output?

AI amplifies what's already there. Weak platforms get worse — reviewer capacity is the rate-limiter of fleet throughput.

Good looks like: mature CI/CD, quality gates, review planned as the constraint.

15 — The mandatewhat a good instrument must do

Eight functions. Miss one and the instrument lies in a way that feels like insight.

Before any dashboard, these are the non-negotiables. The green lights mean the function is live, not optional.

F1 · baseline

Capture the before

No baseline, no attribution. Most teams adopt AI and declare victory with no picture of what came before.

F2 · whole lifecycle

Measure every phase

Plan through operate, not only coding. AI shifts cost between phases, so a coding-only lens miscounts both ways.

F3 · balance

Pair throughput with quality

Never report speed alone. Throughput stands beside stability, quality and developer wellbeing, always.

F4 · attribute

Compare, don't assume

Controlled comparison against a cohort, never a naive before-and-after that blames everything on the tool.

F5 · segment

Tag the authorship

AI-authored, AI-assisted or human. Read every quality number per cohort, because benefit and bill land apart.

F6 · resist gaming

Counter every proxy

Each output metric is paired with an outcome metric, so neither side can be gamed in isolation.

F7 · roll up to value

Reach the P&L

Climb from activity to business outcome and ROI — the only altitude that survives the question "did it matter?"

F8 · govern

Prove provenance

The instrument panelterms, defined

Every acronym on this page, in plain language.

DORA — four keys
DevOps Research & Assessment. Deploy frequency, lead time, change-failure rate and time-to-restore — two speed, two stability, so neither games alone.
DXI
Developer Experience Index. A survey score for how productive and unblocked engineers actually feel — the human side a throughput number misses.
SPACE
A productivity framework spanning Satisfaction, Performance, Activity, Communication and Efficiency — so productivity is never read off one number.
Baseline
The pre-AI snapshot you measure every later change against. No before, no attribution.
DiD — difference-in-differences
A causal method comparing an adopting team against one that didn't, before and after — isolating the tool's effect from everything else moving at once.
Cohort · staggered adoption
Groups that switch on AI at different times, so each acts as the other's control without a formal trial.
Counter-metric
A guardrail bolted to every speed metric, so "faster" can never quietly mean "worse" without showing up.
Lead vs lag
A fast-moving leading signal always shown with its slow-moving lagging outcome — the gain next to its pending bill.
AI-segmentation
Tagging each unit AI-authored, AI-assisted or human, then reading every quality number per group — benefit and bill land on different cohorts.
Provenance
A verifiable record of who or what produced an output, and how — a measurement input now, a legal one under the EU AI Act.
P&L
Profit and loss. The business bottom line every result must eventually reach to count as real.
CAB
Change Advisory Board. The human gate that authorises production changes — an enterprise control agents never touch directly.
EU AI Act
The EU regulation whose high-risk-system duties — identity, provenance, audit — apply to AI used in the SDLC as the timeline phases in.
METR
The research group behind the 2025 randomised trial where developers felt ~20% faster but measured ~19% slower. Its early-2026 continuation narrowed the measured effect to ~−4% (not statistically significant) and concluded AI "likely provides productivity benefits" — the 2025 magnitude is historical; the durable point is the felt-vs-measured gap.

Stop weighing output.
Start weighing the margin.

The legacy tax was always going to be paid by someone. AI made output cheap — but the governed work, the review, the verification, the judgment at the gate, is where the value was hiding all along.
