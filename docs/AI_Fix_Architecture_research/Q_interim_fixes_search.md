# Q. Interim quick fixes for the 10 AI web search failures

Research date 2026-10-26. Every page in the ledger was opened in this session, with WebFetch or the built-in browser. Each quick fix below is something a team can start this week with tools it already pays for. It is a setting in an existing product, a manual practice or an instruction line. None needs a new purchase.

How to read it. "Who" is the one group that owns the first move. Effort hours are illustrative estimates, not measured. The switch-over signals in "Replaced by and when" are illustrative thresholds we suggest, not figures from a source. The evidence shows that each setting or practice exists. No opened page measures how much any of these quick fixes reduces the failure.

Evidence ladder: 1 independent peer reviewed or regulator, 2 primary vendor or standards doc, 3 own observation, 4 independent survey or study, 5 vendor claim of results, 6 press, 7 not opened. A preprint is not peer reviewed, so it sits at rung 4 here. [vendor] marks a page where the maker describes its own feature.

## Quick fixes

| Problem | Quick fix | Who | Effort (illustrative) | Does not cover | Replaced by and when | Ledger id |
|---|---|---|---|---|---|---|
| S1 Citation does not hold | Name one checker per team who opens every cited link in AI output bound for a client or the board and confirms the page holds the cited sentence, logging the first 20 claims checked. Claude web search already returns the cited text, and for web fetch citations must be turned on. | Team heads and HR | 2 hours to set up, then about 2 hours a week per checker | It samples claims rather than checking all of them, and it misses wrong claims that carry no citation. | P1 claim check and P9 named checkers, when hand checks pass about 50 claims a week or the log shows more than 1 in 20 claims unsupported | Q-S01, Q-S02, Q-S03 |
| S2 Silent failure | Reject any AI research report that lists no opened sources, and have the platform team flag every API response that carries a search error code, because those errors arrive inside a normal success response. In ChatGPT deep research, read the activity history before using the report. | Platform and architecture | 4 hours to add the flag and the rejection rule | A search that runs but finds nothing returns an empty list, not an error, and chat users may skip the activity history. | P3 failure log, when flagged errors pass what one person can read each week, about 20 | Q-S04, Q-S05, Q-S06 |
| S3 Stops too early | For multi-part questions, use deep research in ChatGPT or Gemini and have the requester edit the shown research plan so every sub-question is listed before research starts. | Team heads and HR | 1 hour to brief the team, then 5 to 10 minutes per question | The tool can still stop early on one sub-question, and neither plan screen reports what was looked for and not found. | P2 source and date rules, when research moves into an API workflow with no plan screen, or more than 10 reports a week need a coverage check | Q-S07, Q-S08 |
| S4 Planted sources win | Write a 20 to 50 site list for one high-stakes workflow and load it as an allow list in a tool you have: Sites > Manage sites in ChatGPT deep research, the domain list on the Claude Console Capabilities page, or allowed_domains in the OpenAI and Perplexity APIs. | Platform and architecture | 4 to 8 hours to build and load one list | A planted page on an allowed site still gets through, and Perplexity caps the list at 20 domains per request. | P2 source and date rules and P9 named checkers, when a second workflow needs its own list or lists need monthly review | Q-S09, Q-S10, Q-S11, Q-S12 |
| S5 Stale facts | Add a line to Claude organization instructions telling the model to state today's date and the source date beside every price, rule and person in a role. In API work, show each result's page_age, fetch with use_cache set to false, or set the Perplexity search_recency_filter. | Platform and architecture | 2 to 4 hours | page_age is when the site was last updated, not the date of the fact, and an instruction is a prompt the model may not always follow. | P2 source and date rules, when an audit sample still finds undated figures in client work | Q-S13, Q-S14, Q-S15, Q-S16 |
| S6 Snippets, not pages | In API workflows, request the sources field and keep only citations whose URL shows an open_page action (OpenAI), or add the web fetch tool with citations turned on so quotes come from the fetched page (Claude). | Platform and architecture | 1 to 2 developer days | Chat products give no such switch, and the OpenAI page says open_page is reported for reasoning models. | P1 claim check and P3 failure log, when more than one workflow needs the opened-page rule | Q-S17, Q-S18, Q-S19 |
| S7 Blocked pages | Each team head runs the team's top 10 sources through the approved AI tool this week, notes which fail to open, and sets "download the file and upload it" as the route for those sources. | Team heads and HR | 2 to 3 hours per team | It is a one-time test, and it does not solve paywalled sources the company has no licence for. | P3 failure log, when fetch errors need to be counted by source every week rather than tested once | Q-S20, Q-S21, Q-S22 |
| S8 False premise | Add one line to Claude organization instructions asking the model to list the assumptions in a research question and mark any it could not confirm, and leave the call to the reader. ChatGPT Enterprise has a Workspace Instructions setting that may serve the same role. | Platform and architecture | 1 hour plus 2 hours of testing | A 2026 preprint found a "check premises" instruction made a model dispute sound premises too, so every flag needs a human read. | P2 source and date rules and P9 named checkers, when false flags waste more reviewer time than the premises they catch | Q-S16, Q-S23, Q-S31 |
| S9 Memory beats search | For prices, rules and office holders, force a search on every API call (OpenAI tool_choice set to required), and add a Claude organization instruction to cite a dated primary source or say none was found. | Platform and architecture | 2 to 4 hours | Forcing a search does not stop the model trusting a wrong page over a correct memory. | P1 claim check and P2 source and date rules, when changing facts appear in more than one client deliverable a week | Q-S24, Q-S16, Q-S03 |
| S10 Planted instructions | Turn off Claude in Chrome for the organization or limit it to a short allowlist, and place staff with email, payment or file access in a ChatGPT Lockdown Mode role. | Security | 2 to 4 hours | Read-only search can still be steered by planted text, and ChatGPT roles add up, so one permissive role can restore access. | P4 agent fence, when any browsing agent needs to act on email, payments or files | Q-S25, Q-S26, Q-S27, Q-S28, Q-S29, Q-S30 |

## Gaps

- No opened page measures whether any quick fix reduces its failure. The ledger proves each setting or practice exists, nothing more.
- S8 has the weakest footing. The only opened study on premise-check prompts (Q-S23, a single-author preprint) found they backfire, with 57% false challenges. The quick fix therefore asks the model to mark assumptions and leaves the decision to a person.
- ChatGPT Enterprise Workspace Instructions (Q-S31) exists, but no opened page says it reaches the model in every chat. It is named as a possible second vendor for S5, S8 and S9, not a verified one.
- The Claude Console domain list (Q-S10) covers the API. No opened page showed a domain allow list for web search inside the claude.ai chat product for Team or Enterprise.
- Microsoft 365 Copilot and Perplexity Enterprise admin consoles were not checked. Their settings may cover S4 and S10 but are not in this ledger.
- The OpenAI open_page detail was re-read on 2026-10-26 in the V11 check. The page line is "`open_page`, which represents a page being opened. Supported in reasoning models."
- Gemini Deep Research, Perplexity, OpenAI API and Claude API pages show no page date. Help center dates are relative ("7 days ago") and were turned into calendar dates from the research date.
- No quick fix in this set uses a contract letter. None of S1 to S10 targets P7 contract terms.
- S7 has no setting that fixes a blocked page. The quick fix is a manual test plus an upload route, backed only by vendor pages that show fetch limits.
